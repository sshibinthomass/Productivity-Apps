# Cloudflare Mini-Sites and Email Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Firebase with a Cloudflare Worker, D1, R2, Better Auth email/password accounts, Resend transactional email, and public mini-sites at `links.shibinthomas.com/{slug}` while keeping the frontend on GitHub Pages.

**Architecture:** The existing React/Vite bundle is deployed to GitHub Pages at `app.shibinthomas.com` and is also attached to the Worker as static assets for public mini-site rendering. One Worker branches by hostname: `api.shibinthomas.com` serves Better Auth and JSON endpoints, while `links.shibinthomas.com` serves published sites and R2 assets. D1 is authoritative for users, sessions, sites, quotas, publication snapshots, and analytics; R2 stores private and published media.

**Tech Stack:** Node.js 22.12+, React 19, Vite 8, Vitest 4, Better Auth 1.6.25, Cloudflare Workers/Wrangler 4.114.0, Cloudflare D1, Cloudflare R2, Cloudflare Turnstile, Resend 6.18.0, GitHub Pages.

## Global Constraints

- Remove every active Firebase runtime dependency and Firebase deployment path.
- Use email/password authentication only; do not add Google or other social login.
- Require a verified email before normal account access.
- Creating, editing, publishing, deleting, uploading, and viewing analytics require the owning authenticated user.
- Published mini-sites are readable without authentication.
- Enforce no more than five mini-sites per user in both the API and D1.
- Preserve template selection and the start-from-scratch option.
- Keep the existing 40-block, 25-link, and 5 MiB upload limits.
- Use secure HTTP-only cookies; never persist authentication tokens in local storage.
- Permit credentialed CORS only from `https://app.shibinthomas.com` and the configured local development origin.
- Keep the R2 bucket private and serve only approved published objects through the Worker.
- Store `BETTER_AUTH_SECRET`, `TURNSTILE_SECRET_KEY`, and `RESEND_API_KEY` only as Worker secrets.
- Do not delete Firebase resources until a read-only inventory confirms there is no user site data to migrate.

Create the tables with explicit defaults and indexes. The quota trigger must
be:

```sql
CREATE TRIGGER mini_sites_limit_before_insert
BEFORE INSERT ON mini_sites
WHEN (
  SELECT COUNT(*)
  FROM mini_sites
  WHERE owner_id = NEW.owner_id
) >= 5
BEGIN
  SELECT RAISE(ABORT, 'site_limit');
END;
```

Use `slug TEXT NOT NULL COLLATE NOCASE UNIQUE`,
`draft_json TEXT NOT NULL CHECK(json_valid(draft_json))`,

expiration. `user_consents` stores the Better Auth user ID, terms/privacy
version `2026-07-26`, and server timestamp; it never trusts a browser-supplied
acceptance timestamp.

- [ ] **Step 4: Configure Better Auth**

Implement:

```js
export function createAuth(env, dependencies = {}) {
  const email = dependencies.email ?? createEmailSender({
    apiKey: env.RESEND_API_KEY,
    from: env.EMAIL_FROM,
    appOrigin: env.APP_ORIGIN,
  })

  return betterAuth({
    baseURL: env.API_ORIGIN,
    basePath: '/auth',
    secret: env.BETTER_AUTH_SECRET,
    database: env.DB,
    trustedOrigins: [env.APP_ORIGIN, env.DEV_ORIGIN].filter(Boolean),
    emailAndPassword: {
      enabled: true,
      minPasswordLength: 10,
      requireEmailVerification: true,
      revokeSessionsOnPasswordReset: true,
      sendResetPassword: ({ user, url }) =>
        email.sendPasswordReset({ user, url }),
    },
    emailVerification: {
      sendOnSignUp: true,
      sendOnSignIn: true,
      autoSignInAfterVerification: true,
      sendVerificationEmail: ({ user, url }) =>
        email.sendVerification({ user, url }),
    },
    advanced: {
      crossSubDomainCookies: {
        enabled: true,
        domain: '.shibinthomas.com',
      },
    },
  })
}
```

Before forwarding sign-up, sign-in, resend, and reset-request paths to Better
Auth, read `X-Turnstile-Token`, validate it server-side, and enforce these D1
limits:

- sign-up: 5 attempts per normalized email/network pair per 15 minutes;
- sign-in: 10 attempts per normalized email/network pair per 15 minutes;
- resend verification: 3 attempts per normalized email/network pair per hour;
- password-reset request: 3 attempts per normalized email/network pair per
  hour.

Do not include the Turnstile token in JSON persisted by Better Auth. Successful
sign-up also requires `X-Consent-Version: 2026-07-26`; after Better Auth returns
the new user ID, insert the server timestamp and matching terms/privacy version
into `user_consents`.

The script fails if runtime source, `package.json`, or active workflows contain

ignores historical design documents.

Implement the scan with fixed roots so it does not inspect unrelated untracked
directories:

```js
import { readFile, readdir } from 'node:fs/promises'
import path from 'node:path'

const roots = ['src', 'worker', '.github/workflows']
const files = ['package.json']
const patterns = [
  /firebase\//i,
  /firebase-functions/i,
  /firebase-admin/i,
  /VITE_FIREBASE_/,
]

async function collect(directory) {
  for (const entry of await readdir(directory, { withFileTypes: true })) {
    const target = path.join(directory, entry.name)
    if (entry.isDirectory()) await collect(target)
    else files.push(target)
  }
}

for (const root of roots) await collect(root)
const matches = []
for (const file of files) {
  const text = await readFile(file, 'utf8')
  if (patterns.some((pattern) => pattern.test(text))) matches.push(file)
}
if (matches.length) {
  console.error(matches.join('\n'))
  process.exitCode = 1
}
```
